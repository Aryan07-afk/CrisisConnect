Phase 1 — Local Setup & Database Seeding

1

MongoDB URI not being read (undefined)

Critical

node seed.js failed with The uri parameter to openUri() must be a string, got "undefined".

Root cause: two problems in the .env file — the variable was named MONGODB_URI while the code reads process.env.MONGO_URI, and every line had leading whitespace, so dotenv registered keys like " MONGO_URI".

Fix: Renamed the variable to MONGO_URI and rewrote the .env with no leading spaces.
2

Incomplete Atlas connection string

High

The copied URI still contained the <db_password> placeholder and no database name, which would have landed all data in the default test database.

Fix: Replaced the placeholder with the real credentials and appended /crisisconnect before the query string.
3

Seed script validation errors

Medium

Seeding failed twice with Mongoose validation errors:

  • `food` is not a valid enum value for path `skills.0` — the script used request types ("food", "water") as volunteer skills, but the User schema only allows medical / rescue / logistics / communication / general.
  • peopleCount (0) is less than minimum allowed value (1) — a broken random-integer helper could produce 0.
Fix: Mapped request types onto valid skill enum values and corrected the getRandomInt formula to min + floor(random() × (max − min + 1)), verified over 2,000 samples.

Phase 2 — Backend on Vercel (Serverless)

4

Crash on startup: read-only filesystem

Critical

Every request returned HTTP 500. Logs showed:

Error: ENOENT: no such file or directory, mkdir '/var/task/Crisis_backend/uploads/coordinator-docs'

Root cause: the upload middleware ran fs.mkdirSync() at module load time, but Vercel's serverless filesystem (/var/task) is read-only. The process died before serving any request.

Fix: Wrapped directory creation in try/catch with a fallback to the ephemeral writable /tmp directory when running serverless.
5

Scheduled escalation job can't run on serverless

High

The escalation service relied on setInterval(checkEscalations, 60000) inside app.listen(). Serverless instances sleep between requests, so the interval never fires reliably.

Fix: Created a protected endpoint GET /api/cron/escalations (authenticated via CRON_SECRET, supporting both Vercel's automatic Authorization: Bearer header and manual x-cron-secret), invocable by Vercel Cron Jobs or any external scheduler. The app now skips listen() entirely when the VERCEL env var is present.

Phase 3 — Frontend Build & Deploy

6

npm peer-dependency conflict breaks install

High

Vercel's build failed at npm install: @vitejs/plugin-react@4.x declares support for Vite 4–7, but the project uses Vite 8. Local installs only worked because of a legacy flag.

Fix: Added Crisis_frontend/.npmrc containing legacy-peer-deps=true so Vercel's npm resolves identically to local development.
7

Case-sensitive filenames break the Linux build

Critical

Vite's bundler failed with an unresolvable import of src/App.jsx. The files on disk were named Homepage.jsx / Homepage.css, but imports referenced HomePage. Windows filesystems are case-insensitive (local builds worked); Vercel's Linux builders are case-sensitive.

Fix: Renamed the files via git mv and ran a full codebase scan confirming every import now matches its target file's exact casing.

Phase 4 — Runtime Integration (CORS)

8

Missing CORS headers block browser login

Critical

The API returned successful responses to curl but browsers received Login failed: the backend's CORS_ORIGIN didn't include the frontend's production URL, so no Access-Control-Allow-Origin header was emitted. Additionally, requests from Vercel's auto-generated deployment aliases (e.g. *-git-main-*.vercel.app) were rejected because CORS matches hostnames exactly.

Fix: Set CORS_ORIGIN to the frontend URL and replaced the static origin list with a check function that also accepts any crisis-connect-*.vercel.app deployment alias.
9

Double-slash URL from trailing slash in env var

Critical

Even after the CORS fix, login produced net::ERR_FAILED. The browser console revealed the true culprit:

POST https://crisis-connect-sandy.vercel.app//api/auth/login net::ERR_FAILED

VITE_API_URL had been configured with a trailing slash; axios concatenated it with /api, producing //api/... — a path Vercel's router doesn't map to the backend function, so requests never arrived (and carried no CORS headers).

Fix: Corrected the environment variable, and hardened axios.js to strip trailing slashes from VITE_API_URL at runtime so the class of bug cannot recur.
